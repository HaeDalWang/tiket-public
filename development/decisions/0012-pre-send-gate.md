# 0012. 초안과 발송 사이에 관문을 둔다

- **언제**: 2026-09-07
- **정한 것**: `tickets/<번호>.md` 에 `## 발송 전 점검` 6항목을 두고, 초안을 쓴 뒤 발송 전에
  통과시킨다. 항목은 전부 **실제로 나갔던 실패**에서 뽑았다.

- **왜**: 다른 엔지니어가 워크스페이스를 돌려 티켓 100012 초안을 만들고 내부 메모로 남겼다.
  내용은 사실상 맞는데 **"고객의 결에 맞지 않는다"** 는 평가가 나왔다.
  실제 발송문과 대조해 보니 톤 문제가 아니라 **이미 있는 규칙을 어긴 것**이었다.

  `playbooks/reply-style.md` 에 *"고객이 추가 왕복 없이 실행할 수 있도록"*,
  *"제품명과 공개 화면명은 정확히 유지한다"* 가 이미 적혀 있었다. 초안이 둘 다 어겼다.
  **규칙이 없어서가 아니라 지켜지지 않아서 생긴 실패**이므로, 규칙을 더 쓰는 대신
  발송 전에 강제로 대조하는 관문을 만들었다.

- **100012 초안을 이 관문에 넣으면 6개 중 3개가 걸린다**:
  - 고객이 문의 첫 문단에 **"조회 권한이 없어 AWS콘솔상으로 확인이 어렵다"** 고 썼는데,
    초안은 AWS 콘솔 Inventory 를 안내했다. 고객이 못 여는 화면이다
  - 콘솔 경로를 영문으로만 적었다. 실제 발송은 한글 UI 명칭 + 스크린샷 3장이었다
  - 구매 방법을 이미 답하면서 "계정명을 회신해 주시면 안내드리겠습니다" 로 왕복을 하나 더 만들었다

- **항목 6개와 근거 티켓**:

  | 항목 | 나온 곳 |
  |---|---|
  | 고객이 밝힌 제약을 답변이 지키는가 | 100012 — 권한 없다고 쓴 고객에게 콘솔 경로 안내 |
  | 물어본 것 전부에 답했는가 | 100007 — 오류 2개 중 1개만 다룸 |
  | 콘솔 경로를 고객이 보는 화면 그대로 썼는가 | 100012 — 영문 vs 한글 UI |
  | 지금 답할 수 있는데 되묻고 있지 않은가 | 100012 — 불필요한 왕복 |
  | `[확인]` 에 전부 출처가 붙었는가 | 100003·100007 ([[0010-investigation-output-locked]]) |
  | 비용 수치가 빌링 플랫폼 정제값인가 | 기존 절대 경계 |

- **버린 선택지**:
  - **고객 수준 레벨링** — 처음 제안된 방향이었다. 검토 결과 맞지 않는다. 캠핑톡 개발팀은
    `Compute SP / 1년 / $0.50 / Partial Upfront` 를 정확히 명시하고 권장사항 엑셀까지
    첨부한 고객이다. **수준이 낮아서 생긴 문제가 아니다.** 갈린 것은 수준이 아니라
    ① 고객이 이미 밝힌 환경·제약을 반영했는가 ② 매체 선택(스크린샷 vs 텍스트)이었다.
    레벨링은 실체 없는 축을 하나 더 만드는 일이 됐을 것이다.
  - **규칙 문서를 더 쓰기** — 이미 있는 규칙이 안 지켜진 상황이라 같은 실패가 반복된다.
  - **항목을 더 넣기** — 6개를 넘기면 형식적으로 체크하게 된다. 실제 실패에서 나온 것만 둔다.

- **같이 정리한 것**: `playbooks/reply-writing-rules.md` 의 `Two-layer contract` 는
  [[0001-drop-the-heavy-ticket-format]] 에서 폐기한 Decision Packet v2 / Reply Brief v2 를
  쓰라고 지시하고 있었다. 현재 구조(산출물 선택 → `## 확인한 것` 근거 → 스타일 → 관문)로
  교체했다. 폐기된 산출물을 가리키는 지시가 남아 있으면 읽는 쪽이 어느 쪽을 따를지 모른다.

- **고정 방법**: `validate_workspace.py` 가 템플릿에서 `## 발송 전 점검` 과 세 항목 문구를,
  `reply-writing-rules.md` 에서 관문 연결과 콘솔 언어·제약 규칙을 검사한다.
