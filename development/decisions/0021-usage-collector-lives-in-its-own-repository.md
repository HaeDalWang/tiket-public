# 0021. 수집기는 별도 저장소에 둔다 — 계약은 여기, 구현은 밖

- **언제**: 2026-09-21

- **정한 것**: 사용 지표 수집기(Lambda + API Gateway + DynamoDB)를 **`example-org/tiket-usage-collector`**
  에 둔다. 이 저장소에는 `terraform/` 을 넣지 않는다. 클라이언트(`scripts/report_usage.py`)와
  이 결정 기록만 여기 남는다.

- **왜 이 논의가 나왔나**: 배포는 했는데 어떻게 쓰이는지 측정이 안 된다. 피드백을 요청해도
  오지 않는다 — 이 프레임워크는 "구조를 안 봐도 된다"가 장점이라, 동료에게 구조 의견을
  달라는 것은 **안 해도 된다고 약속한 일을 해달라는 요청**이다. 그래서 능동 피드백 대신
  쓰기만 해도 나오는 부산물을 모은다. 클라이언트는 `c1f2b3d` 로 이미 있었고 받는 쪽이 없었다.

- **왜 밖인가**: [[0014-do-not-vendor-the-external-skill]] ·
  [[0015-onboarding-installs-the-external-skill]] · [[0018-install-through-bootstrap-not-a-clone]]
  이 이미 **구현체는 밖, 계약은 안**을 확립했다. 더해서

  - `CLAUDE.md` 가 "Actual Terraform and implementation code lives under `~/work/<customer>/`
    or another designated project" 라고 정한다
  - 배포 비대칭 — 수집기는 **한 사람이 한 번** 배포하고, 프레임워크는 **전원이 매일** 쓴다
  - `.terraform/`, lock 파일, backend 설정이 `validate_workspace.py` 의 `TEXT_SUFFIXES`·
    ASCII 경로·정본 파일 목록에 전부 예외를 요구한다
  - `export_framework_snapshot.py` 의 `UPSTREAM_DIRS` 가 allowlist 라, 넣지 않으면
    저장소에 있는데 동료에게 안 나가는 유령 디렉터리가 된다

  **스키마 드리프트가 유일한 반대 논거였다.** 해결은 스킬과 같다 — 계약을 여기 두고 구현만
  밖에 둔다. v1 은 `schema_version` 정수 하나로 충분하다. JSON Schema 파일은 v2 에서
  필요해지면 만든다.

- **로컬 배치**: `~/work/tiket-usage-collector/`. `~/work/` 은 고객사 디렉터리 전용이라
  맞지 않는다. `~/work/` 에는 이미 같은 org 의 저장소가 있다.

- **확인한 사실** (2026-09-21):

  - state backend 는 **이미 있었다.** MSP 팀이 이 계정·리전에서 쓰는 S3 버킷과 락 테이블이
    전날 만들어져 있었고, 부트스트랩이 필요 없었다.
  - **그 버킷은 다른 프로젝트(주간회고 웹사이트 인프라)의 것이다.** 당시 버킷은 비어 있고
    그쪽은 아직 로컬 state 를 쓰고 있었다 — 즉 그쪽 `key` 가 안 정해져 충돌 위험이 실재했다.
  - Terraform 공식 문서: *"DynamoDB-based locking is deprecated and will be removed in a
    future minor version."* 대체는 `use_lockfile` 이고, 락 파일이 `<key>.tflock` 으로
    state 옆에 생겨 **key 와 함께 자동으로 격리된다.**

- **그래서 공유하는 것은 버킷 이름 하나뿐이다**:

  - `key` 를 `tiket-usage-collector/` prefix 로 격리한다
  - `use_lockfile = true` 를 쓰고 `dynamodb_table` 을 지정하지 않는다 → 남의 락 테이블을
    **한 번도 건드리지 않는다**

- **실행 권한**: 사람의 자격이 아니라 IAM 롤을 assume 한다. 배포자가 바뀌어도 권한이 같고,
  롤을 신뢰하는 계정 어느 쪽의 프로필로도 실행된다. `provider` 와 `backend` **양쪽에 따로**
  걸어야 한다 — backend 는 provider 설정을 상속하지 않아 provider 에만 걸면 state 버킷이
  403 이다. 문법도 다르다(provider 는 블록, backend 는 attribute). backend 블록이 변수를
  못 받아 ARN 이 두 군데 적히고, 그 사실을 수집기 README 에 적어뒀다.

- **수집기는 클라이언트를 신뢰하지 않는다**: `report_usage.py` 의 `assert_no_identifiers` 는
  **그 장비의 코드**다. 동료가 옛 버전을 쓰거나, 누가 고쳤거나, 직접 POST 할 수 있다.
  그래서 같은 금지 패턴 표를 서버에서 다시 검사한다. 걸리면 저장하지 않고 `422` 와 함께
  **어느 패턴인지만** 돌려준다 — 값은 응답에도 로그에도 남기지 않는다.

  표가 두 곳에 복제된다. **복제인 것을 알고 한다** — 서버가 클라이언트 코드를 import 할 수
  없고, 이 표는 거의 안 바뀐다. 바뀌면 양쪽을 같이 고친다.

- **엔드포인트 URL 은 저장소에 두고, API 키는 아예 없앴다**: 두 번 옮겼다.

  처음에는 URL·키 둘 다 저장소 밖에 두려 했다. 먼저 **URL 을 안으로 들였다** — URL 은
  팀에 하나뿐인데 전원이 손으로 붙여넣으면 오타 난 사람의 지표만 조용히 사라진다.
  이 저장소는 private 이다.

  그 다음 **키를 없앴다.** 사람이 키를 나눠주는 절차가 실제로 배포를 막고 있었다 —
  동료들이 그 단계에서 멈췄다. 그리고 논리적으로도 남길 이유가 없었다: 키를 같은
  저장소에 두면 **키를 아는 사람 = 저장소를 볼 수 있는 사람 = URL 을 아는 사람**이라
  키가 URL 과 구분되지 않는다. 방어력은 키를 없앤 것과 같은데 SSM 파라미터·회전 절차·
  온보딩 입력이 아무것도 지키지 않으면서 유지돼야 한다.

  | 남은 방어 | |
  |---|---|
  | private 저장소 | 엔드포인트를 아는 사람이 팀으로 제한된다 |
  | throttle | burst 10 / rate 5 |
  | 금지 패턴 재검사 | 식별자가 섞이면 저장하지 않고 `422` |

  **이 결정은 페이로드가 메트릭 전용이라는 데 기댄다.** 최악이 "가짜 통계가 섞인다"
  수준이라 성립한다. 페이로드에 식별자가 들어가기 시작하면 되돌려야 한다.

  회전에 해당하는 것은 **엔드포인트를 새로 만드는 것**이다. `DEFAULT_TELEMETRY_URL` 을
  고치고 동료가 `git pull` 하면 끝나고, 각자 입력할 것이 없다.

- **동의는 conf 에 남은 기록이다**: 키가 없어지면서 "키를 받은 사람만 보낸다"는 옵트인
  장치가 사라졌다. 그 자리를 **`~/.config/msp/tiket-usage.conf` 의 `TIKET_ENGINEER`**
  가 대신한다 — 온보딩 7/8 단계에서 고지를 보고 이름을 정한 사람에게만 생기는 줄이다.
  `--if-due` 는 환경변수가 아니라 **conf 만** 본다. 동의는 이 장비에 남은 기록이어야지
  세션 환경변수로 켜질 일이 아니다.

  끄는 방법은 이름을 지우는 것이 아니라 같은 파일의 `TIKET_TELEMETRY=off` 다.

- **온보딩은 셸 프로필을 건드리지 않는다**: 계획 단계에서는 환경변수로 심으려 했으나
  이 저장소에는 이미 반대 원칙이 있다(`test_neither_touches_a_shell_profile`) — 프로필을
  고치면 그 셸을 안 쓰는 사람에게서 조용히 실패한다. Zendesk 자격증명과 같은 방식으로
  conf 파일에 쓴다. 환경변수는 **덮어쓰기 용도로만** 남긴다(conf 보다 우선).

- **표시 이름의 기본값은 Zendesk 상담사 이름이다**: 온보딩 6단계에서 이미 본인 Zendesk
  자격증명을 넣는다. `GET /api/v2/users/me.json` 의 `.user.name` 은 `git config user.name`
  보다 사람 이름에 가깝고, **추가 입력을 요구하지 않는다.** 실패하거나 자격증명이 없으면
  조용히 `git config user.name` 으로 떨어진다 — 지표 이름 때문에 온보딩이 멈추면 안 된다.

  **이름이 이메일 형태면 쓰지 않는다.** 그런 Zendesk 계정이 있고, 그대로 실으면 수집기가
  `422 forbidden pattern: email` 로 거절해 그 사람 지표만 조용히 사라진다.

- **전송 시점은 세션 시작 훅, 하루 1회**: freshness 와 같은 세 호스트(Claude Code·Codex·
  Kiro)에 걸되 **별도 훅**으로 둔다 — 관심사가 다르고 한쪽이 죽어도 다른 쪽이 돈다.
  선언은 `render_agent_configs.py` 한 곳이고 호스트 파일은 얇은 어댑터다(0020 과 같은 구조).

  훅은 `--send` 가 아니라 `--if-due` 를 부른다. 스로틀·무출력·실패 무시가 전부 그 안에 있다.

  | 지킨 것 | 어떻게 |
  |---|---|
  | 세션을 막지 않는다 | 무엇이 실패해도 `return 0`. 타임아웃 3초(기본 10초는 세션 시작에 길다) |
  | stdout 을 오염시키지 않는다 | `--if-due` 는 아무것도 출력하지 않는다. freshness 가 겪은 문제다 |
  | 하루 1회 | `~/.config/msp/tiket-usage-sent` 스탬프. check-freshness 와 같은 방식 |
  | 고지 전인 사람을 안 건드린다 | conf 에 `TIKET_ENGINEER` 가 없으면 조용히 끝낸다 |

  **스탬프는 성공이 아니라 시도에 찍는다.** 성공에만 찍으면 네트워크가 종일 죽은 날 매
  세션 재시도한다. 지표는 부수적인 일이고 세션 시작을 늦추는 쪽이 더 나쁘다 — freshness
  가 "뒤처진 동안은 안 찍는다"로 간 것과 반대인데, 그쪽은 **알림을 놓치면 안 되는** 일이고
  이쪽은 **하루치 지표를 놓쳐도 되는** 일이라 그렇다.

- **`engineer` 는 자기 신고다**: 위조할 수 있다. 이것은 **감사 로그가 아니라 사용 통계**라
  그 수준이 맞다. API 키를 아예 두지 않는 판단도 같은 근거에 선다 — 최악이 "가짜 통계가
  섞인다" 수준이다. raw 를 보냈다면 전부 달라졌을 것이다.

- **고정 방법**: 수집기 저장소의 `lambda/test_handler.py` 16개 — 금지 패턴 7종, 크기 상한,
  `schema_version`, 인증(미설정 서버가 전부 거절하는지 포함). 이 저장소 쪽은
  `test_report_usage.py` 의 `JsonOutputTests` 3개가 `--json` 의 stdout 이 순수 JSON 으로
  유지되는지 지킨다.

- **배포 전에 잡은 버그**: `report_usage.py --json` 이 stdout 마지막에 사람용 안내를 찍어
  **JSON 파싱이 깨졌다.** 그대로 뒀으면 수집기가 `400 malformed json` 을 돌려줬을 것이다.
  실제 출력을 서버 검사 함수에 통과시켜 보고 발견했다. 사람용 줄을 stderr 로 옮겼다.

- **아직 안 한 것**:
  - **실제 Kiro·Codex 세션에서 지표 훅이 발동하는지 확인하지 않았다.** 스키마는
    freshness 훅과 같은 렌더러를 쓰고 TOML 파싱까지 확인했으나, 발동은 **가설**이다.
    0020 이 남긴 것과 같은 한계다.
  - 자동 전송 시점(세션 시작 훅 + 하루 1회 스로틀)과 고지 방식은 정하지 않았다.
  - 대시보드는 만들지 않는다. v1 은 DynamoDB 를 직접 조회한다. 귀찮아지면 그때 만든다.
  - **비용은 추정이다.** 이 규모면 월 1달러 미만으로 보지만 단가를 조회하지 않았다.
    첫 달 Cost Explorer 로 확정한다.
  - 수집기가 빌려 쓰는 롤은 다른 프로젝트의 것이다. 그쪽에서 롤을 지우거나 신뢰 범위를
    조이면 배포가 멈춘다. 전용 롤 분리는 ARN 두 곳만 바꾸면 된다.
