# 0002. `tickets/` 는 로컬 전용, 마스킹은 하지 않는다

- **언제**: 2026-09-04
- **정한 것**: 티켓 작업 기록은 `tickets/<번호>.md` 에 **실명 그대로** 쓴다. `CUST-NNN`
  발급도 매핑 조회도 하지 않는다. 대신 gitignore + pre-push 로 저장소 밖으로 못 나가게 막는다.
- **왜**: 경영진·팀 리드가 고객사명·정보를 한곳에 모으는 데 부담 없다고 확인해 주셨다.
  어차피 엔지니어와 상급자가 알아야 하는 정보다. 그러면 **비식별 시점이 "항상, 미리"에서
  "밖으로 낼 때, 한 번"으로 이동**한다. 다른 엔지니어들이 헷갈려한 원인이 정확히 이
  "쓰기 전에 가명부터 발급" 절차였다.
- **버린 선택지**:
  - **`CUST-NNN` 유지** — 매번 `.private/customer-map.md` 를 열어 대조해야 한다.
    보호 대상이 저장소 밖으로 안 나가는 파일인데 비용만 남는다.
  - **`customers/` 를 통째로 삭제** — `profile.md` 는 티켓 흔적이 아니라 계약·청구 주체·
    CoC 담당자다. validator 가 스키마를 강제하고(`validate_workspace.py:926-946`) 비용·계약
    답변 전에 필요하다. 지우지 않고 "먼저 만들 것"에서 "필요할 때 만들 것"으로 격하했다.
- **수용한 위험**: 엔지니어 노트북마다 실명 자료가 백업 없이 쌓인다. 나중에 한꺼번에
  비식별해야 할 때가 사고 나기 좋은 순간이다. 완화는 판례 증류를 작고 검토 가능한 단위로
  두는 것 — 아직 설계 안 됨([[0005-classify-before-answering]] 이후 과제).
- **검증**: `git add -f` 로 강제 추가한 뒤 관리자 override(`TIKET_ALLOW_UPSTREAM_PUSH=1`)까지
  써도 pre-push 가 막는 것을 실제로 확인했다.
