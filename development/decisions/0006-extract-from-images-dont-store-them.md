# 0006. 이미지는 보관하지 않고 핵심만 뽑아 적는다

- **언제**: 2026-09-05
- **정한 것**: 티켓 이미지는 필요할 때 받아서 **읽고**, 기록에는 **거기서 뽑은 사실만**
  텍스트로 남긴다. 이미지 파일 자체는 저장소에 두지 않는다.
- **왜**: 이미지는 검색도 diff 도 안 되고 용량만 차지한다. 반면 그 안의 정보는 답변의
  근거가 된다. 100008 에서 실제로 나온 것:
  - 적용한 CloudTrail 이벤트 선택(관리 이벤트만, 읽기+쓰기) — 본문엔 "아래와 같이"뿐
  - `mng-sys-tail-log` 버킷 정책을 콘솔이 읽지 못했다는 경고 배너
  - SSO 이벤트 → 사용자·앱 매핑 방법(`onBehalfOf.userId`, `serviceEventDetails.app-id`)
  셋 다 텍스트에는 한 글자도 없었다.
- **딸린 발견**: Zendesk 는 본문에 붙여넣은 이미지를 `attachments` 배열에 안 넣고 본문
  마크다운 링크로만 남기기도 한다. `attachments` 만 세면 이미지 4장짜리 티켓이 "첨부 없음"
  으로 보이고, **읽는 쪽은 자기가 뭘 못 봤는지조차 모른 채 답변을 쓴다.** 둘 다 센다.
- **버린 선택지**:
  - **이미지를 `tickets/` 에 같이 저장** — 로컬 전용이라 보안 문제는 아니지만, 다시 볼 때
    사람이 열어봐야 하고 기록으로서 쓸모가 없다.
  - **자동 다운로드** — 스레드에는 실명·계정ID가 들어 있다. 어디에 남길지는 호출자가
    정해야 하므로 `--images <디렉터리>` 로 명시할 때만 받는다.
- **보안**: 자격증명은 우리 Zendesk 호스트에만 보낸다. 티켓 본문에 고객사 자체 헬프데스크
  URL 이 섞여 있고(100008 은 `support.billing.example.com`), 거기에 Authorization 헤더를 붙이면
  우리 토큰을 제3자에게 넘기는 것이 된다. 테스트로 고정.
