# 0010. 조사 결과 + 답변 형식 확정 — 출처 없는 [확인] 은 [확인] 이 아니다

- **언제**: 2026-09-07
- **정한 것**: 장애·비용·보안사고·자문 건의 산출물 형식을 확정한다. 핵심 규칙 하나:
  **`[확인]` 에는 출처가 반드시 붙는다.** 없으면 `[확인]` 이 아니다.
  출처는 문서 URL + 확인 날짜, 또는 조회 명령·첨부 이미지·청구서 라인·케이스 회신.

- **왜**: 등급을 세 개로 나눠도 `[확인]` 을 아무 데나 붙일 수 있으면 장식이 된다.
  실제 티켓 두 건에 적용해 보니 이 규칙이 매번 무언가를 잡았다.

- **적용 결과** (100003 dnk labs, 100007 한국일보):
  - **문서상 메커니즘과 이 계정에서 실제 일어난 일은 다르다.** 100007 은 두 오류의 원인을
    문서로 확인했지만 어느 쪽이 걸렸는지는 계정 조회를 안 해 `[모름]` 으로 남겼다.
    이 구분이 없으면 그럴듯한 원인을 확정처럼 쓰게 된다.
  - **출처가 공개 문서가 아닌 경우를 구분한다.** 100003 의 "환불 불가"는 AWS 케이스 회신이고
    공개 문서에 같은 문장이 없다. 다른 고객에게 재사용할 때 케이스를 다시 여는 게 안전하다.
  - **이미지 안에만 있는 사실이 있다.** 100003 에서 AWS 가 과금 7개월 전인 2026-01-13 에
    PHD 로 통보한 사실은 스크린샷에만 있었다. 텍스트에는 없다.
  - **내가 지어낸 명령어를 잡았다.** 100003 판례에 `describe-db-engine-versions` +
    `SupportedEngineLifecycleSupport` 를 적었는데 **명령명도 필드명도 존재하지 않았다.**
    문서 확인 단계에서 걸렸다. 맞는 것은 `describe-db-major-engine-versions` +
    `SupportedEngineLifecycles` 다.

- **`[모름]` 에는 확인 방법을 같이 적는다** — 가능하면 실행할 명령까지. 확인 경로 없는
  `[모름]` 은 그냥 포기다.

- **유선 처리도 `## 실제 발송` 에 남긴다**: 100007 은 유선 한 줄로 끝나 티켓에 내부 메모만
  남았다. 그 결과 고객이 보고한 오류 두 개 중 하나만 다뤄졌고, 다음에 같은 문의가 와도
  참고할 것이 없다. 통화는 티켓에 남지 않으므로 사람이 옮겨 적어야 한다.

- **버린 선택지**:
  - **등급만 쓰고 출처는 선택** — 원안. 등급이 장식이 된다.
  - **`[확인]` 을 자동 검사** — `tickets/` 는 gitignore 라 validator 가 볼 수 없다.
    지금은 템플릿 문구와 리뷰로 강제한다.

- **고정 방법**: `validate_workspace.py` 가 `templates/ticket-intake.md` 에서
  `출처 없는 [확인] 은 [확인] 이 아니다` · `확인 방법:` · `유선으로 처리했으면` 문구를 검사한다.

- **덤으로 확정된 업무 규칙**: Anthropic use case 양식의 조직 단위 일괄 제출은 기술적으로
  가능하지만 **MSP 회사 Payer 에서 대신 누르지 않는다** (담당자 확인). 양식은 회사명·업종·
  사용 목적을 제출하는 것이라, 관리 계정에서 하면 한 고객사의 사용 목적이 전 고객사에 걸린다.
  고객사가 자체 Payer 를 운영할 때 그 고객사에게 안내할 수 있는 선택지일 뿐이다.
