# 0039. 지표 전송이 세 번 연속 실패하면 세션 시작 때 에이전트에게 알리라고 말한다

- **언제**: 2026-10-07
- **정한 것** (유지보수자 — "스타트 훅에서 전송 테스트 같은 걸 해서 실패하면 … 프롬프트를 못 넣나"):
  - `report_usage.py --if-due` 는 수집기에 닿지 못한 횟수를 센다(`tiket-usage-sent-status` 의 `failures`). 닿으면 0 으로 돌아간다.
  - **세 번째 연속 실패부터** stdout 에 알림을 낸다 — 호스트가 그것을 에이전트 맥락에 넣는다. 시도할 때만 나오므로 많아야 6시간에 한 번이다.
  - 알림은 **알리라고만 한다.** 답 끝에 사용자에게 한 줄, 그리고 `report_usage.py --diagnose` 출력을 유지보수자에게 전해 달라고.
    **고치라고 하지 않는다** — 인증서 검증·프록시·시스템 설정·저장소 스크립트를 바꾸지 말라고 적는다.
  - `--diagnose` 를 둔다. 원인을 가릴 것을 한 번에 낸다(Python·버전·프록시 변수 이름·인증서 파일·수집기와 기준 주소 도달·마지막 결과·실제 전송).
- **왜**: 동료 한 명의 PC 가 며칠 동안 한 건도 못 보냈는데 본인도 유지보수자도 몰랐다. 그 PC 의 Python 에 루트 인증서가 없었다.
  수집기에 닿지 못하는 실패는 수집기 로그로 볼 수 없다 — 알 수 있는 곳은 그 PC 뿐이다. 원인을 찾느라 그 동료에게 명령을 세 번 부탁했다.
- **뒤집는 것**: 2026-09-29 에 "전송 실패가 AI 에게 섞이면 안 된다" 고 정하고 훅을 완전히 조용하게 만들었다. 한두 번의 실패는 여전히 조용하다.
  며칠째 못 보내는 것은 잡음이 아니라 고장이라서 예외를 둔다.
- **스스로 고치게 하지 않는 이유**: "전송이 되게 하라" 는 지시는 검증을 끄거나 프록시를 바꾸는 쪽으로 가기 쉽다. 동료 PC 에서 승인 없이 도는
  세션(Kiro `Trust All Tools`)도 있다. 흔한 원인(인증서)은 코드가 스스로 넘는다 — `scripts/https_fetch.py` 가 OS 인증서 묶음으로 다시 시도한다.
- **실측** (kiro-cli 2.28.0, 사람 없이, 빈 폴더에 탐침 훅):
  - `SessionStart` 명령 훅의 stdout 은 **에이전트에게 간다** — "1 더하기 1" 을 물었는데 답 끝에 탐침 문구를 옮겨 알렸다.
    (0038 에서 안 간다고 잰 것은 `PostFileSave`·`PostToolUse`·`Stop` 이다.)
  - 같은 회차에 `AgentSpawn` 훅은 돌지 않았다.
- **모르는 것 · 한계**:
  - 실제 문구로 에이전트가 `--diagnose` 를 돌리고 **아무것도 고치지 않는지**는 재지 않았다. Claude Code·Codex·Kiro IDE 도 안 봤다.
  - 이름이 금지 패턴에 걸리는 경우는 이 알림이 아니라 수집기 쪽 사유 행(`skipped`)으로 보인다 — 닿기는 하기 때문이다.
  - 훅 자체가 안 도는 PC(상위 폴더를 열어 쓰는 경우)는 여전히 아무도 모른다.
- **근거**: `scripts/report_usage.py`(`FAILURE_NOTICE`, `write_status`, `diagnose`), `scripts/test_report_usage.py`, `scripts/https_fetch.py`

## 덧붙임 (2026-10-07, 같은 날 검토 뒤)

같은 원칙(알리라고만 하고 고치라고는 안 한다)을 두 곳에 더 썼다.

- **`git fetch` 가 세 번 연속 실패하면** `check-freshness` 가 같은 꼴의 알림을 낸다. 예전에는 스탬프만 찍고 끝나 그 PC 는 영영 안 올라갔다.
- **훅이 끝나기 전에 죽은 것도 실패로 센다.** 시작할 때 `started` 와 스탬프를 먼저 적는다 — 죽은 시도는 끝난 뒤에 쓰는 기록을 못 남긴다.

교훈 후보 전송 실패는 알리지 않는다. 본인이 할 수 있는 일이 없다(대개 수집기의 거절이다) — 다음 사용 지표에 `lessons_status` 로 실어 유지보수자가 본다.
보내는 쪽 장치는 여기까지다. 훅이 아예 안 도는 PC 는 받는 쪽(사이트의 "N일째 안 옴")에서만 잡힌다.
