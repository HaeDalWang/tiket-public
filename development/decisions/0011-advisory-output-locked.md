# 0011. 답변 + 출처 형식 확정 — 문서 충돌을 조용히 넘기지 않는다

- **언제**: 2026-09-07
- **정한 것**: 자문·문의 건의 산출물 형식을 확정한다. 세 산출물 중 마지막.
  [[0010-investigation-output-locked]] 의 출처 규칙을 그대로 쓰되 두 가지를 더한다.
  1. **공식 문서끼리 충돌하면 충돌 사실을 기록하고, 어느 쪽을 왜 신뢰하는지 밝힌다.**
     조용히 한쪽을 고르지 않는다.
  2. **고객에게도 문서 링크를 같이 준다.** 우리 말을 믿으라고 하지 않는다.

- **왜**: 이 유형은 조회할 리소스가 없어서 **지어내기 가장 쉽다.** 그럴듯한 서비스명·
  룰셋명·옵션명이 근거 없이 나온다. 실제 티켓(100010)에서 그게 그대로 일어났다.
  - 담당자가 1차 회신에서 VPN·프록시 차단에 `AWSManagedRulesAmazonIpReputationList` 를
    권했고, **하루 뒤 스스로 정정**했다 — 맞는 것은 `AWSManagedRulesAnonymousIpList` 였다.
  - 이름이 비슷하고 둘 다 "IP 목록"이라 헷갈린다. 형식대로 문서를 먼저 열었으면
    처음부터 안 틀렸을 지점이다.

- **문서 충돌은 실제로 있다**: 같은 건을 확인하다 AWS 문서 두 개가 어긋나는 것을 발견했다.
  DDoS 백서는 `AnonymousIPList` 규칙이 `AWSManagedRulesAmazonIpReputationList` 안에
  있다고 적고, 관리형 룰그룹 레퍼런스는 `AWSManagedRulesAnonymousIpList` 안에 있다고 적는다.
  레퍼런스가 정본이다(WCU·레이블 네임스페이스까지 명시). **백서를 근거로 답하면 틀린 룰셋을
  안내하게 된다.** 담당자가 헷갈린 원인도 이것일 수 있다.

- **대조 방법**: 고객이 쓴 표현을 **문서 원문과 직접 맞춰본다.** 100010 에서 고객은
  "VPN·외부 호스팅 업체"라고 썼고, 레퍼런스 문서에 *"VPNs, proxies, Tor nodes, and web
  hosting providers"* 가 그대로 있었다. 이름의 유사성이 아니라 대상의 일치로 고른다.

- **버린 선택지**:
  - **조사형(0010)과 통합** — 겹치는 부분이 많아 검토했다. 하지만 이 유형에만 있는 위험이
    있다: 조회할 것이 없어 **틀려도 티가 안 난다.** 조사형은 값이 안 나오면 막히지만
    자문형은 그럴듯한 답이 끝까지 나온다. 별도 규칙이 필요하다.
  - **충돌 시 최신 문서 우선** — 날짜로 정하면 블로그가 레퍼런스를 이긴다. 문서 종류로
    판단하는 것이 맞다.

- **고정 방법**: `validate_workspace.py` 가 `templates/ticket-intake.md` 에서
  `공식 문서끼리 충돌하면` 문구를 검사한다.
