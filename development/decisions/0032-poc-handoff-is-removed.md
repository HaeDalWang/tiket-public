# 0032. PoC 인계(`handoff/`)를 없앤다

- **언제**: 2026-10-02
- **정한 것**: `handoff/`(안내문·의뢰서·결과서 양식)를 지우고 가리키던 문장을 전부 걷어낸다 — `CLAUDE.md`, `AGENTS.md`, Kiro 스티어링,
  라우터, `capability-catalog` 의 `poc-handoff`, `compatibility.md`, `install-verification.md`, `infra-change-process.md`,
  `GUIDE-ONBOARD-001`, 검사기의 필수 파일·문구, 내보내기 목록. "실제 코드는 `~/work/<customer>/` 에 둔다" 는 경계는 `CLAUDE.md` 에 그대로 있다.
- **왜**: 쓰는 사람이 한 명도 없었다(유지보수자). 의뢰서도 결과서도 만들어진 적이 없다 — `tickets/` 19건 중 이 양식을 가리키는 기록 0건.
  그런데 세 진입점과 라우터가 매 세션 이 절차를 싣고 있었다. 이 저장소가 하는 일(티켓 조사와 초안)과 결이 다르다.
- **버린 선택지**:
  - Terraform 기반 실험 환경으로 키운다 — 실험 계정·모듈·상태·비용·정리 절차가 필요한 별개의 제품이다. 여기 담기에는 크다.
    만든다면 별도 저장소로 하고, 그때 tiket 에는 의뢰와 결과 확인 몇 줄만 둔다
  - 일시 중단으로 남긴다 — `customers/`(0031)와 달리 다시 열 조건이 없다. 양식은 git 이력에 있다
- **남는 한계**: "돌아온 결과는 직접 확인한 뒤에 답변에 쓴다" 는 문장이 같이 사라졌다. `CLAUDE.md` 의 "recalled documentation and
  prior replies are not proof" 와 발송 전 점검이 같은 일을 한다고 보고 따로 남기지 않았다. `PoC` 라는 말 자체는 정책 카드와
  플레이북에 일반 용어로 남아 있다.
- **근거**: `CLAUDE.md` 4,367 → 4,227자, 필수 파일 42 → 39. 검사기는 문장을 지운 직후 11건으로 실패했고 요구를 뺀 뒤 통과했다
