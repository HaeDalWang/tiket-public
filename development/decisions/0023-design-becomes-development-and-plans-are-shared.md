# 0023. `design/` 을 `development/` 로 바꾸고, 계획서와 백로그를 공유한다

- **언제**: 2026-09-24
- **정한 것**:
  - 폴더 이름을 `design/` → `development/` 로 바꾼다. 결정·실측·미결에 더해 **할 일과 방향**까지 담는다.
  - `backlog.md` 를 새로 둔다. 하기로 했지만 안 한 것, 그리고 지금 방향.
  - 루트에 있던 계획서·검토서 3건을 `plans/` 로 옮기고 **추적한다.** `.gitignore` 의
    `framework-review-*.md`·`improvement-plan-*.md` 를 지운다.

- **왜**: 남은 일이 세 군데에 흩어져 있었다 — gitignore 된 루트 계획서 3건, 에이전트
  개인 메모리, 유지보수자 머릿속. 셋 다 동료에게 안 보인다. 계획서 Phase 0-2·0-3 은
  2026-09-14 에 정하고 열흘째 안 됐는데, 그 사실을 아는 곳이 계획서 한 장뿐이었다.
  `design` 이라는 이름은 "왜 이렇게 만들었나"만 담는다고 읽혀서 할 일을 둘 자리로 안 보였다.

- **버린 선택지**:
  - **이름은 두고 `backlog.md` 만 추가** — 비용은 가장 싸다(참조 20곳을 안 고친다).
    다만 유지보수자가 명시적으로 이름 변경을 원했고, 되돌리는 비용도 `git mv` 한 번이다.
  - **GitHub Issues/Projects** — 동료가 clone 한 곳에서 안 보이고, 결정 기록과 떨어진다.
    에이전트가 저장소 안에서 바로 읽을 수 있는 쪽을 골랐다.
  - **계획서를 계속 gitignore** — 원래 이유는 "개인 의견 문서, 프레임워크가 아니다"였다.
    프레임워크가 아니라는 건 맞다. 그래서 배포본에서는 계속 빠진다 (`export_framework_snapshot.py`
    가 `development/` 를 `workspace-owned` 로 분류). 하지만 팀 공유를 막을 이유는 아니었다.

- **수용한 위험**: 계획서가 이제 팀에게 보인다. 추적 전에 `validate_workspace.py` 의
  비식별 검사를 통과시켰다. 원래 개인 문서로 쓰여서 말투가 1인칭·대화체인 곳이 있다 — 고치지 않는다.

- **근거**: `development/README.md` "넷이 어떻게 이어지나", `development/backlog.md`,
  `scripts/test_export_framework_snapshot.py` (배포본에 `development/` 가 없는지 확인)

- **2026-09-24 정정**: 위 "왜" 의 "계획서 Phase 0-2·0-3 은 열흘째 안 됐다" 는 **틀렸다.**
  `8a031d7`(2026-09-14)이 이미 처리했다 — 옮기면 export 에서 빠지는 위치라 `DISTRIBUTION.md`
  가 없는 파일을 가리키게 되므로, 옮기지 않고 `TECHNICAL.md` 와 두 파일 머리에 "티켓 경로에서
  로드되지 않는 설치·배포 문서" 라고 표시하는 것으로 끝냈다. 백로그를 계획서만 보고 채우고
  git 이력을 대조하지 않은 탓이다. 이 결정의 나머지(흩어진 할 일을 한 곳에 모은다)는 그대로다.
