# 0005. 답하기 전에 준비도로 먼저 분류한다 (A/B/C)

- **언제**: 2026-09-05
- **정한 것**: 티켓을 받으면 **주제보다 먼저 "답할 준비가 됐는가"로 등급을 매긴다.**
  등급이 산출물 자체를 바꾼다.

  | 등급 | 상태 | 산출물 |
  |---|---|---|
  | A | 대상·증상 다 특정됨 | 답변 초안 |
  | B | 일부만 특정됨 | 부분 답변 + 확인 요청 |
  | C | 대상 자체가 불명 | **되물음 질문지만** |

  두 번째 축은 "우리가 할 일" — 안내 / 조사 / 대행 / 위임. 긴급도(장애·보안)는 축이 아니라
  순서를 바꾸는 덮어쓰기로 둔다.

- **왜**: 기존 분류는 주제 분류뿐이었다(조회/트러블슈팅/비용/RI·SP/보안/EOL/행정 —
  외부 스킬 `reference/analysis-playbook.md`). 주제는 *어디를 볼지*는 정해주지만
  *답할 수 있는 상태인지*는 말해주지 않는다. 실제로 갈리는 건 후자다.
  티켓 100008 은 고객이 계정ID·ARN·SAML Issuer 디코딩까지 다 해온 A 등급이었고,
  `"SSO 로그인 안돼요"` 같은 C 등급은 조회할 대상조차 없다. 같은 방법으로 칠 수 없다.
- **핵심**: **C 티켓에 답변 초안을 쓰면 안 된다.** 되물음이 산출물이고, 되물음도 잘해야
  한다 — 열 개 물어보면 고객이 지친다. 최소 질문으로 최대 정보가 목표다.
- **버린 선택지**:
  - **주제 분류만 쓰기** — 0점 티켓을 100점 티켓과 같은 절차로 처리하게 된다.
  - **긴급도를 축으로 세우기** — 등급과 직교하지 않는다. 순서만 바꾸므로 덮어쓰기가 맞다.
- **아직 안 한 것**: 실제 티켓 20~30건을 훑어 등급 분포와 C 등급의 실제 모습을 확인하는 것.
  지금 A/B/C 는 표본 하나(100008)와 추정에 기반한다. 표본을 보고 쪼개기를 조정한다.

## 2026-09-05 개정 — 1순위에서 예외 처리로 내림

실측([[2026-09-05-ticket-sample-65]]) 결과 준비도 분포가 **A 84% / B 14% / C 2%** 였다.
84%가 한 등급에 몰리면 분류가 정보를 거의 주지 않는다. "0점 티켓이 분명히 있을 것"이라는
전제 자체가 표본에서 확인되지 않았다.

A/B/C 를 폐기하지는 않는다. C 에 답변 초안을 쓰면 안 된다는 판단은 여전히 옳고, 그 2%가
가장 사고 나기 쉬운 구간이다. 다만 **주 분류축에서 예외 처리로 내린다.**
새 순서는 [[0007-machine-first-then-work-type]] 를 따른다.
