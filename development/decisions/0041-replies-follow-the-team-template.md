# 0041. 회신은 팀 답변 템플릿으로 쓴다 — 유지보수자 스타일을 지운다

- **언제**: 2026-10-21
- **정한 것** (유지보수자):
  - 고객 회신의 모양은 팀 「서포트데스크 답변 템플릿」(00 접수 ~ 11 종료, 12개 양식)을 따른다. 원문을 `playbooks/reply-templates.md` 에 그대로 넣는다.
    고객 식별값은 없다. 원문은 2026-10-20 팀 회의에서 거의 확정됐다 — 최종 수정본으로 보고 미리 맞춘다.
  - `playbooks/reply-style.md`(유지보수자 스타일)를 지운다. 그 파일 스스로 "회신 템플릿이 고정되면 없어진다" 고 적어 두었다.
    모양이 아니라 내용인 원칙(다음 질문 미리 답하기, 쉬운 말, 절차를 한 줄에 압축하지 않기)은 `reply-writing-rules.md` 로 옮긴다.
  - **번호 절차는 남긴다.** 고객이 따라 할 단계는 `▪` 블록 아래에 번호로 붙인다 — 팀 리드가 "엔지니어가 정리해 안내하는 편이 낫다" 고 했다.
  - 원문 체크리스트에서 새로 생긴 셋(직접 확인 방법, 링크만 보내지 않기, 날짜 일괄 확약 금지)을 `## 발송 전 점검` 에 넣는다(6 → 9항목).
    "공개 댓글로 설정했는가" 는 넣지 않는다 — 보내는 사람이 하는 일이고 에이전트는 보내지 않는다.
  - **비용(04·05)은 `CLAUDE.md` 가 이긴다.** 원문은 공개 요금 기준 참고 금액과 비용 변화 수치를 허용하지만, 고객에게 나가는 금액은 빌링 플랫폼 정제값만 쓴다.
    원문 "내부 확인 사항" 의 비용 업무 분장이 확정되면 다시 본다.

- **산출물 3종(0008)은 그대로다.** 산출물은 에이전트가 무엇을 만드는지, 회신 유형은 고객에게 어떤 모양으로 나가는지라 서로 겹쳐 쓴다.
  기록 머리에 `회신 유형:` 을 둔다. 검사기는 아직 이 칸을 보지 않는다 — 쓰이는지 기록을 보고 정한다.

- **미룬 것** (2단계): 템플릿이 전제하는 티켓 흐름 전체(02 중간 안내, 05·07 이관 때 내부 재확인 주체·일정 기록, 10 티켓 밖 처리, 11 무응답 해결).
  원문 "내부 확인 사항"(진행 안내 주기, 무응답 대기 기간, 티켓 상태)이 정해져야 값을 넣을 수 있다.

- **2단계 일부, 2026-10-21 같은 날** (유지보수자):
  - 원문 "내부 확인 사항" 은 **아직 안 정해졌다** — 무응답 해결 대기 기간, 진행 안내 주기, 비용 문의 분담. 값을 지어내지 않고 비워 둔다.
  - 기다리는 동안 티켓 상태는 다들 **보류**로 둔다. 상태는 사람이 바꾼다.
  - 사람에게 물어 결정하는 것(기술 담당자·상급자·다른 부서)은 기록의 `## 내부 확인` 에 남긴다. 에이전트는 물을 거리를 정리하고,
    사람이 답을 받아 적는다. 답이 비면 02·05·07 로 쓴다. 검사기는 아직 이 칸을 보지 않는다 — 평가에서 쓰이는지 먼저 본다.
  - 10(티켓 밖 처리)은 지금 흐름에 없다 — 에이전트가 유선·메신저 협의를 모른다. 사람이 원문 양식을 직접 쓴다.

- **개정 1, 2026-10-23** (유지보수자, 모듈 점검): 원문을 "그대로" 넣던 것을 줄인다. 에이전트가 쓰지 않는 세 덩어리 — 원문 "발송 전 체크리스트"(기록의
  `## 발송 전 점검` 으로 이미 옮겼다), 10 티켓 밖 처리 양식(사람이 직접 쓴다), "내부 확인 사항"(아직 안 정해졌다) — 를 `reply-templates.md` 에서 뺀다.
  회신마다 읽히는 파일이라 약 2,450자가 매번 든다. 원문 전체는 팀 문서에 있다. 팀 템플릿이 바뀌면 통째로 바꿔 넣지 말고 바뀐 양식만 옮긴다.
