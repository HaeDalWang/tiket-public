# 0014. 외부 스킬을 저장소에 넣지 않는다 — 대신 온보딩이 찾아주고 안내한다

- **언제**: 2026-09-07
- **정한 것**: `aws-customer-account-ops` 스킬을 `tiket` 저장소에 벤더링하지 않는다.
  온보딩 스크립트가 **소스 저장소를 찾아주고, 설치 명령을 안내하고, 설치 상태와 사본
  드리프트를 확인**한다. 설치 자체는 `support-skills` 의 `install.sh` 가 한다.

- **왜 이 논의가 나왔나**: 신규 엔지니어가 매번 담당자에게 스킬을 요청해야 해서
  설정이 느리다. "그냥 워크스페이스에 미리 넣어두면 되지 않나"가 제안됐다.

- **확인한 사실**:
  - `support-skills` 에는 **remote 가 있다** — `https://github.com/example-org/support-skills.git`
    (회사 GitHub org, 엔지니어 계정만 접근 가능).
    다른 엔지니어가 직접 clone 할 수 있다. **병목은 배포가 아니라 저장소 접근 권한이다.**
    담당자에게 요청할 것은 파일이 아니라 접근이고, 그건 한 번만 하면 된다.
  - `install.sh` 에 **`EXTERNAL_ID`** 가 하드코딩돼 있다(`install.sh:535` 부근).
    cross-account AssumeRole 의 보안 통제값이다. 함께 `API_URL`, `CLIENT_ID`,
    `CROSSACCOUNT_ROLE_ARN`(Payer 계정 ARN)도 들어 있다. **값 자체는 여기 옮겨 적지 않는다** —
    옮겨 적으면 이 문서가 곧 유출 경로가 된다.
  - **스킬 본체에는 비밀값이 없다.** `get-sts-token.sh` 안의 URL 은 `xxx.execute-api...`
    placeholder 다. 즉 위험한 것은 스킬이 아니라 설치 관리자다.
  - `install.sh` 는 이미 `--status`(감지된 에이전트 표시), `--all`, `--select` 를 갖고 있다.
    **우리가 재구현할 것이 없다.**

- **벤더링을 버린 이유**:
  - **보안** — `install.sh` 를 같이 넣으면 `EXTERNAL_ID` 와 Payer 계정 ARN 이 배포본에
    실린다. 안 넣으면 설치가 안 되므로 반쪽짜리가 된다.
  - **버전 드리프트** — 이미 에이전트별 사본 4개를 `csg-login` 마커로 관리 중이다
    ([[0004-verify-powershell-from-the-start]] 주변 실측). 저장소 안에 5번째 사본이
    생기면 `self-update.sh` 와 충돌하고, 저쪽이 1.8 을 내면 우리 것만 1.7.2 로 남는다.
  - **소유권** — 다른 개발자가 활발히 개발 중인 코드다. 사본을 들고 있으면 그쪽 변경을
    우리가 따라가야 한다.

- **대신 온보딩이 하는 일** (5단계 `customer-skill`):
  - `csg-login` 마커로 설치 여부와 **실제 실행 경로**를 확인
  - 설치된 사본들의 해시를 비교해 **드리프트를 잡는다** — `self-update` 부분 실패가
    여기서 드러난다
  - 미설치면 소스 저장소를 후보 경로에서 찾고, 있으면 설치 명령을, 없으면 clone 명령을
    URL 과 함께 제시한다 (`SUPPORT_SKILLS` 환경변수로 경로 지정 가능)
  - 대화형 실행일 때는 `install.sh --status` 결과를 그대로 보여준다

- **같이 추가한 것** (온보딩 4→7단계):
  - `agents` — 설치된 에이전트 9종을 나열하고 각각 스킬 보유 여부 표시
  - `mcp` — 호스트 설정 4개 존재 + `verify_mcp_servers.py` 실제 연결.
    exit 2(전제 미비·네트워크)는 실패가 아니라 `건너뜀` 으로 구분한다
  - Hermes 는 MCP 설정을 저장소 밖에 두므로 **자동 확인 불가**를 명시하고 넘어간다

- **자동화할 수 없는 것** (정직하게 남긴다):
  - 스킬 설치 자체 — 소스 저장소 접근이 필요하다
  - Hermes MCP 정렬 — 프로필이 저장소 밖에 있다
  - Slack 로그인 — 브라우저 대화형

- **고정 방법**: `test_onboarding_parity.py` 가 에이전트 경로 테이블 9개가 양쪽에 같이
  있는지, 드리프트 검사가 양쪽에 있는지, 그리고 **`skills/` 디렉터리가 저장소에 생기지
  않았는지**를 검사한다. 마지막 항목이 이 결정을 강제한다.
