# 0017. 이 프레임워크는 외부 하네스 없이 서는 것을 전제한다

- **언제**: 2026-09-11
- **정한 것**: 저장소는 별도의 하네스나 개인 글로벌 에이전트 지침 **없이** 설계·운영되는 것을
  전제한다. README 에 이 전제를 명시하고, 개인 설정을 끄거나 줄이도록 **권고**한다.
  강제하지 않는다 — 개인 설정은 개인 것이다. 대신 충돌 시 저장소 규칙이 우선한다는
  사다리를 전면에 내놓는다.

- **왜 이 논의가 나왔나**: 다른 엔지니어가 워크스페이스를 시험하다 두 가지를 보고했다.
  (1) 세션 첫 메시지에 티켓 번호를 줬는데 라우팅 절차를 건너뛰었다.
  (2) 나중에 티켓 기록은 만들었으나 산출물 없이 "① ② ③ 중 뭘 할까요" 로 끝냈다.

- **1차 진단 (저장소 텍스트 결함) — 확인됨**:
  - `CLAUDE.md` 의 `Absolute boundaries` 에 `confirm capability status in
    agents/runtime-status.md **first**` 가 있었고, 이것이 번호 절차(`Start and route`)보다
    **위에** 있었다. 위에서부터 읽는 에이전트는 4번(capability-catalog)만 하고 1~3번을 건너뛴다.
    관측된 행동이 정확히 그 모양이었다.
  - `agents/task-router.md` 는 `playbooks/infra-change-process.md:18` 의
    "Stop at the human gate — **provide the artifact and evidence**" 를
    "Stop at the human approval boundary" 로만 줄여 담고 있었다. 진입점이 라우터이므로
    잘린 절반이 실제로 작동했다.
  - 둘 다 고쳤고(`672528d`), 문장 자체를 마커로 고정했다(`525fe5e`).
    0013 은 같은 병의 *삭제* 형태였고 이번은 *요약* 형태다. 존재 검사만으로는 요약을 못 잡는다.

- **2차 진단 (환경) — 가설이지만 방향이 일치한다**:
  그 세션은 비대한 개인 글로벌 지침 아래에서 돌고 있었다. 거기에는 언어·문체 규칙,
  다수의 `rules/*.md` 임포트, 서브에이전트를 선제적으로 쓰라는 지시, "막히면 물어봐라" 류가
  함께 들어 있었다. 두 증상(시작점 분산, 질문으로 종료)과 방향이 정확히 같다.
  **저장소 텍스트만 고치면 절반만 고치는 것이다.**

- **그래서 정한 것**: 프레임워크의 전제를 암묵이 아니라 **문서화된 계약**으로 올린다.
  - README 에 `전제 — 이 프레임워크는 혼자 선다` 절 추가. 무엇이 저장소 안에 이미 있는지,
    외부 지침이 어떤 방식으로 깨뜨리는지(관측/가설 구분), 그리고 우선순위 사다리.
  - `CLAUDE.md` 에 한 줄. 사람이 README 를 안 읽어도 에이전트는 런타임에 알아야 한다.

- **왜 강제하지 않나**: 개인 글로벌 설정은 사용자 소유다. 저장소가 그것을 끄게 만들 권한도
  수단도 없다. 할 수 있는 것은 **전제를 밝히는 것**과 **충돌 시 우선순위를 정해두는 것**뿐이다.
  사다리 자체는 새로 만들지 않았다 — `playbooks/reply-writing-rules.md:52` 에
  `team rules → operator-local preference` 로 이미 있었다. 묻혀 있던 것을 전면에 꺼냈다.

- **이 결정의 한계**:
  - 권고는 검사할 수 없다. 어떤 사용자가 어떤 글로벌 지침을 켜고 있는지 저장소는 알 수 없다.
  - 2차 진단은 **가설**이다. 같은 티켓을 글로벌 지침을 끈 환경과 켠 환경에서 각각 돌려
    비교하면 확정된다. 아직 하지 않았다.
  - 텍스트 수정과 마커 고정은 **재발 방지**지 예방이 아니다. 새로운 절차 누락은 여전히
    사람이 트랜스크립트를 읽어야 발견된다. 절차 준수를 검사 가능한 산출물로 만드는 것
    (`tickets/<번호>.md` 검사기)은 별도 안건으로 남겨둔다.
