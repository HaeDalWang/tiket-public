## 1. 한 줄 목표

tiket 의 `policy/` · `playbooks/` · `pitfalls/` 를 **최신 정식 버전 그대로** 종류별로 보여 주고 검색한다. **보기만** 한다.

## 2. 가장 중요한 원칙 — 복사하지 않는다

사이트 저장소에 파일을 복사하면 tiket 에서 카드 하나를 고치는 순간 둘이 달라진다. 폐기된 규칙이 사이트에 살아
있으면 누군가 그걸 보고 고객에게 답한다. **화면과 릴리스가 달라지면 안 된다** (tiket 개발 지도와 같은 원칙).

그래서 사이트가 tiket 저장소의 **가장 높은 `vX.Y.Z` 태그**를 직접 읽는다.

- 동료들의 AI 가 쓰는 것과 정확히 같은 버전이다 — 자동 업데이트도 태그만 따라간다 (tiket 0025)
- main 에만 있고 릴리스 안 된 내용은 보이지 않는다
- 화면 맨 위에 "**v0.1.3 기준** · 3분 전 동기화" 를 늘 보인다

## 3. 구조

```
GitHub example-org/tiket ──(읽기 전용 배포 키, 10분마다 fetch)──▶ EC2 호스트: 동기화 스크립트
      │                                                          └─ 최신 태그의 허용 경로만 풀어 둔다
      │                                                             /opt/msp-weekly-review/knowledge/current → v0.1.3/
      ▼                                                                  │ (읽기 전용 마운트)
                                                                  앱 컨테이너: src/knowledge.mjs → /api/knowledge…
```

**동기화는 호스트에서, 앱은 파일만 읽는다.** 이유:

- 배포 키는 지금처럼 root 만 읽는 호스트에 둔다. 컨테이너에 SSH 키와 git 을 넣지 않는다
  (사이트 저장소 배포 키가 이미 이렇게 쓰인다 — `terraform/user_data.sh.tpl`)
- 앱은 git 을 모른다. 폴더 하나와 `VERSION` 파일만 본다 — 테스트가 쉽다

### 3.1 동기화 스크립트 (호스트, systemd timer 10분)

1. `git -C /opt/tiket-mirror fetch --tags --prune` — bare 미러. 처음이면 `git clone --mirror`
2. 태그 중 `^v(\d+)\.(\d+)\.(\d+)$` 만 골라 **숫자로** 가장 높은 것 — 글자순이 아니다(`v0.10.0` > `v0.9.0`).
   tiket `scripts/release_tags.py` 와 같은 규칙이다
3. 이미 그 태그가 `current` 면 끝
4. `git archive <tag> -- <허용 경로>` 를 새 폴더 `knowledge/<tag>/` 에 풀고, `VERSION`(태그·커밋·동기화 시각)을 쓴 뒤
   `current` 심링크를 **원자적으로** 바꾼다(`ln -sfn` 후 `mv -T`). 반쯤 풀린 폴더를 앱이 읽지 않게
5. 옛 버전 폴더는 둘까지만 남긴다
6. 실패하면 `current` 를 건드리지 않고 로그만 남긴다. `VERSION` 의 동기화 시각이 늙어 가므로 화면이 알아챈다(5절)

**허용 경로 (이것만 읽는다 — "무엇을 뺄지" 가 아니라 "무엇을 넣을지" 로 적는다)**

```
policy/_routing.md  policy/README.md  policy/cards/  playbooks/  pitfalls/
```

`customers/`·`tickets/`(고객 내용), `policy/raw/`·`policy/inbox/`(규정 원본)는 git 에 애초에 없어 태그에도 없다.
그래도 허용 목록으로 적는다 — 나중에 누가 tiket 에 새 폴더를 추가해도 사이트에 저절로 흘러오지 않게.

### 3.2 배포 키

- `example-org/tiket` 에 **읽기 전용** 배포 키 하나. 비밀키는 Secrets Manager `msp-weekly-review/tiket-deploy-key`
- 앱 역할 IAM 의 `GetSecretValue` 대상에 그 ARN 을 더한다(지금 `app_github_deploy_key` 정책과 같은 방식)
- SSH 설정은 호스트 별칭을 따로 둔다(`Host github-tiket`) — 사이트 저장소 키와 섞이지 않게
- **미확인: example-org 조직이 저장소별 배포 키를 허용하는지.** 11절 1번에서 먼저 확인한다. 막히면 대안은
  읽기 전용 fine-grained PAT(Contents: read, 저장소 하나) 또는 GitHub App. 어느 쪽이든 3.1 의 흐름은 같다

## 4. 서버 (`src/knowledge.mjs`, `server.mjs` 에는 등록만)

| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | `/api/knowledge` | 버전 정보 + 세 종류 목록(메타데이터만) |
| GET | `/api/knowledge/:kind/:id` | 문서 하나의 원문 마크다운 + 메타데이터 |
| GET | `/api/knowledge/search?q=` | 제목·본문 검색. 결과는 문서 id·제목·맞은 줄 앞뒤 발췌 |

- **권한: 로그인한 모든 사용자.** 이 내용은 모든 엔지니어 PC 에 이미 배포되는 팀 자산이다
- `:kind` 는 `policy` · `playbook` · `pitfall` 셋만, `:id` 는 **읽어 둔 목록에 있는 것만** 받는다 — 경로를 조립하지 않는다(경로 탈출 차단)
- 폴더는 시작할 때와 `VERSION` 이 바뀌었을 때만 다시 읽는다. 검색은 메모리에서 — 문서가 스무 개 남짓이라 색인 라이브러리가 필요 없다.
  한국어·영어 모두 **대소문자 무시 부분 일치**면 된다
- 설정 `KNOWLEDGE_DIR`(기본 `/knowledge/current`). 없거나 비면 기능·메뉴를 끈다 — 다른 두 화면과 같은 방식

**문서마다 뽑는 메타데이터**

| 종류 | id | 제목 | 그 밖 |
|---|---|---|---|
| policy | 카드 앞머리 `id` | `title` | **`status`**(active·draft·retired), `review_by`, `effective_from`, `source_owner` |
| playbook | 파일 이름 | 첫 `# ` 줄 | — |
| pitfall | 파일 이름 | 첫 `# ` 줄 | — |

`policy/_routing.md` 의 표는 목록 순서와 "트리거 낱말" 검색에만 쓴다. 상태의 원본은 카드 앞머리다.

## 5. 화면 (지식 관리 → "지식 도서관")

- 맨 위: **"v0.1.3 기준 · N분 전 동기화"**. 동기화가 **하루 넘게** 멈췄으면 경고 띠 — "최신 릴리스와 다를 수 있습니다"
- 탭 세 개: **회사 규칙**(policy) · **업무 방법**(playbooks) · **사례**(pitfalls), 개수 표시
- 검색창 하나가 세 탭을 가로지른다. 결과에 종류 배지
- **회사 규칙 탭**
  - 상태 배지: **확정**(active) · **초안**(draft) · **폐기**(retired). 기본 필터는 폐기 숨김
  - 초안 카드를 열면 맨 위에 크게: "**초안 — 참고용입니다. 고객에게 '규정상' 이라고 말할 근거가 아닙니다.**"
    (tiket `CLAUDE.md` · `policy/_routing.md` 의 규칙 그대로)
  - `review_by` 가 지났으면 "검토 기한 지남" — 팀장·경영진이 볼 때 가장 쓸모 있는 신호다
- 문서 보기: 마크다운 렌더링. **원시 HTML 은 그리지 않는다**(XSS). 문서 안의 상대 링크(`pitfalls/x.md`,
  `cards/POLICY-…md`)는 도서관 안의 해당 문서로 바꾸고, 대상이 없으면 글자만 남긴다
- 마크다운 부품: **지금 사이트에 없다**(tiptap 은 편집기, markdown 확장 미설치 — 2026-09-29 확인).
  사이트 규칙대로 더하기 전에 기존 의존성으로 되는지 보고, 안 되면 원시 HTML 을 기본으로 막는 렌더러 하나만 더한다
- 옆 칸(선택): "현장 교훈 승인 대기 N건 →" — 승인이 여기로 이어진다는 걸 보여 준다

## 6. 범위 밖

- 편집 — 원본은 tiket git 이다. 고칠 곳은 tiket 이고, 릴리스를 거쳐 여기 나타난다
- 승인된 교훈이 파일이 되는 자동화 — 지금처럼 사람(+에이전트 초안)
- 옛 버전 비교·이력 보기
- `policy/excerpts/`(규정 발췌) — 카드가 근거 줄을 가리키지만 원문에 가까워 이번엔 뺀다. 필요하면 허용 경로에 더한다

## 7. 검증

실제 GitHub·실제 EC2 에 닿는 자동 테스트는 만들지 않는다.

| 층 | 무엇을 |
|---|---|
| 동기화 스크립트 | 임시 git 저장소로: 가장 높은 태그를 **숫자로** 고르는가(`v0.10.0` vs `v0.9.0`) · 태그 아닌 main 커밋을 무시하는가 · `v0.2.0-rc1` 류를 무시하는가 · **허용 경로 밖 파일이 풀리지 않는가**(`customers/x.md` 를 태그에 넣어 확인) · 실패 시 `current` 가 그대로인가 · 심링크 교체가 원자적인가 |
| 서버 | 앞머리 파싱(`status` 없는 카드는 "상태 모름") · 경로 탈출(`..%2F`)과 목록에 없는 id 가 404 · 검색 대소문자·한국어 · 원시 HTML 이 응답 렌더러에서 막히는가 · 설정이 비면 메뉴 없음 |
| E2E | 가짜 knowledge 폴더로 탭 세 개 · 초안 경고 · 검토 기한 지남 · 검색 · 문서 간 링크 · 동기화 하루 넘으면 경고 |
| 변이 | 숫자 정렬을 글자 정렬로 · 허용 목록 검사 제거 · id 목록 검사 제거 · 초안 경고 제거 — 각각 테스트가 잡는지 |
| 운영 | 배포 뒤 화면의 버전이 `git ls-remote --tags` 의 최고 태그와 같은가. tiket 에서 태그를 하나 더 낸 뒤 10분 안에 바뀌는가 |

## 10. 정해야 할 것

| 질문 | 기본안 |
|---|---|
| 보는 사람 | 로그인한 모든 사용자. 이미 모든 엔지니어 PC 에 있는 내용이다 |
