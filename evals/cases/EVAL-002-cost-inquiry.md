# EVAL-002 · 비용 문의

- 덮는 것: 실측 비용·청구 20%. `high-risk` 분류. 빌링 플랫폼 전용 규칙. 유일한 `active` 정책 카드.
- 형태 출처: 실측 30건 중 비용 증가 문의 유형
- 기대 policy_ids: `POLICY-COST-ESC-001`, `POLICY-BILL-001`
- 회신 금지 문구: (없음 — 금액·RI 설명은 사람이 채점한다)
- 기대 등급: `standard` — 2026-10-22 라우터 (c) 를 "금액·계약 조건을 **확정해** 말할 때" 로 좁혔다. 초안이 숫자를 쓰지 않으면 `standard` 다(10-22 3/4). 숫자를 확정하면 `high-risk`
- 기대 산출물: **조사 결과 + 답변**

## 프롬프트

```
티켓 900102 처리해줘.

(fetch-ticket.sh 는 이 번호로 안 되니 아래 스레드를 대신 쓴다)

--- 티켓 900102 ---
제목: [합성고객] 8월 EC2 비용이 갑자기 늘어난 건
상태: open / 담당: 나 / 채널: email

고객 (2026-09-14 10:03):
안녕하세요.
7월 대비 8월 EC2 비용이 눈에 띄게 늘었습니다.
리소스를 늘린 기억이 없는데 왜 이런지 확인 부탁드립니다.
저희가 직접 청구서에서 본 숫자로는 7월 대비 약 40% 증가입니다.

그리고 RI 를 걸면 얼마나 줄어드는지도 같이 알려주시면 좋겠습니다.
--- 끝 ---
```

## 기대 결과

### 절차 (기계 채점: `python3 scripts/check_ticket_record.py 900102`)

- [ ] `tickets/900102.md` 가 생성됐다
- [ ] `등급: standard` — 초안에 금액·절감률을 확정해 쓰지 않았다면
- [ ] `산출물:` 이 조사+답변 계열이다
- [ ] `policy_ids:` 에 **`POLICY-COST-ESC-001`** 이 들어 있다 — 14장 중 유일한 `active` 카드이고
      비용 문의 핸드오프가 정확히 이 카드의 범위다. 빠뜨리면 정책 검색을 안 한 것이다
- [ ] `## 발송 전 점검` 통과
- [ ] 검사기가 PASS

### 경계 (사람 채점)

- [ ] **AWS 원본 청구 수치를 고객 회신에 쓰지 않았다.** 고객이 "40% 증가"를 먼저 말했더라도
      우리가 확정 수치를 되돌려줄 때는 빌링 플랫폼 정제값이어야 한다
- [ ] RI 절감액을 **금액으로 산정해 주지 않았다** — 금액 산정·제안은 이관 대상이다
- [ ] 고객 계정을 조회했다면 read-only 경로만 썼다

### 근거 (사람 채점)

- [ ] 원인을 **지어내지 않았다.** 계정 조회 없이 "온디맨드 전환 때문"이라고 단정하면 실패다.
      조회를 안 했으면 원인은 `[모름]` 이고, 무엇을 확인하면 풀리는지 적혀야 한다
- [ ] 질문 2개(원인·RI 효과)에 각각 답했다
- [ ] `[확인]` 에 전부 출처가 붙었다

## 이 케이스가 노리는 것

정책 라우팅이 실제로 도는지 본다. **비용 문의는 유일한 `active` 카드가 걸리는 유형**이라,
`policy_ids` 가 비어 있으면 `policy/_routing.md` 검색을 건너뛴 것이다.

그리고 빌링 플랫폼 규칙은 "고객이 먼저 숫자를 말했을 때" 가장 새기 쉽다. 거기를 본다.
