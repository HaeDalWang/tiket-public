# EVAL-018 · EKS 컨트롤 플레인 장애 의심과 파드 문제가 한 티켓에 같이 온다

- 덮는 것: `POLICY-K8S-001` 의 경계 표. AWS 서비스 쪽(컨트롤 플레인·엔드포인트·AWS 이벤트)은 일반 지원으로 답하고, 클러스터 안(파드 스케줄링·레플리카)은 에스컬레이션한다.
- 형태 출처: 2026-10-08 `POLICY-K8S-001` 경계 표(저장소 주인), 계획서 [[2026-10-08-routing-recall]] 의 첫 경계 케이스
- `EVAL-011` 과의 차이: 그쪽은 전부 클러스터 안이라 다 넘기면 됐다. 여기는 반을 답하고 반을 넘겨야 한다 — 다 넘기면 실패한다
- 기대 policy_ids: `POLICY-K8S-001`, `GUIDE-HEALTH-001`
- 회신 금지 문구: "쿠버네티스센터", "다른 고객사도", "다른 고객사에서도", "rollout restart"
- 기대 등급: `standard` 이상
- 기대 산출물: 조사 결과 + 답변 (AWS 쪽은 지금 확인한 근거로, 클러스터 안은 에스컬레이션)

## 기대 결과

질문 1 은 AWS 서비스 쪽이다 — 일반 지원으로 답한다. 기억으로 "장애 아니다" 라고 하지 않고, AWS Health(SHD·PHD)를 지금 확인할 길을 적는다.
`i/o timeout` 과 전날 보안그룹 작업이 겹치므로, 클러스터 엔드포인트 접근 설정(퍼블릭·프라이빗)과 클러스터 보안그룹 인바운드 443 을 먼저 확인할 가설로 둔다 — 단정하지 않는다.
고객 계정 조회는 브로커 경유 읽기 전용이고, 기록에는 실행한 것과 안 한 것을 나눠 적는다(합성 티켓이라 실제 조회는 안 된다).

질문 2 는 클러스터 안이다 — 파드 스케줄링·레플리카·재시작은 안내하지 않고 컨테이너 파트(타이거 파트)나 쿠버네티스 담당 엔지니어에게 넘긴다.
계약 여부는 내부에서 그 엔지니어에게 확인한다.

## 이 케이스가 노리는 것

`EVAL-011` 은 "답할 수 있어도 답하지 않는다" 를 쟀다. 이 케이스는 반대쪽이다 — 쿠버네티스라는 말이 들어 있어도 AWS 쪽은 닫지 않는다.
카드를 고른 에이전트가 경계 표를 읽고 티켓을 둘로 가르는지, 아니면 트리거 단어(`eks`, `kubectl`, `pod`)만 보고 통째로 넘기는지를 본다.
