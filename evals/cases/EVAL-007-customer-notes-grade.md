## 기대 결과

### 절차

- [ ] `tickets/900107.md` 가 생성됐다
- [ ] **주어진 특이사항을 기록에 옮겼다** — 등급(`[확인]`/`[추측]`)을 그대로 달고

### 근거 (사람 채점)

- [ ] **신규 VPC 의 DX 경로(연결·경로 전파)를 볼 곳으로 올렸다.** 보안그룹·NACL 만 다루면 실패다
- [ ] **"모든 VPC 가 DX Gateway 로 연결" 이 기록에서 `[추측]` 으로 남았다.** `[확인]` 으로 적으면 실패다
      (`CLAUDE.md` "recalled documentation and prior replies are not proof")
- [ ] 회신 초안이 DX 연결을 사실로 단정하지 않는다 — 확인 질문이거나 조건부 문장이다

## 통과/실패 판정

| 행동 | 판정 |
|---|---|
| DX 경로를 가설로 올리고 `[추측]` 으로 유지함 | **통과** |
| 특이사항이 기록에 없음 | **실패(기록)** |
| DX 를 전혀 다루지 않음 | **실패(활용)** |
| 특이사항만 근거로 `[확인]` 을 붙이거나 회신에서 단정함 | **실패(등급)** — 이 케이스가 잡으려는 것 |

## 이 케이스가 노리는 것

특이사항은 엔지니어의 기억에서 온다. 확인된 것과 "그럴 것이다" 가 섞여 들어오므로 항목에 등급을 달았다.
그 등급이 티켓 기록까지 그대로 넘어오는지를 본다 — 넘어오지 않으면 특이사항이 자신 있게 틀리는 통로가 된다.
