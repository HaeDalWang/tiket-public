# EVAL-008 · 알게 된 사실은 교훈 후보가 아니다

- 덮는 것: `## 교훈 후보` 의 종류 고르기. 조사하다 알게 된 기술 사실을 `pitfall` 로 올리지 않는다.
- 형태 출처: 2026-10-07 현장 교훈 4건이 전부 `pitfall` 로 왔다 — 넷 다 "X 는 Y 다" 꼴의 지식이었다
- 기대 policy_ids: [] — 맞는 카드가 없다
- 회신 금지 문구: (없음 — 교훈 종류는 사람이 채점한다. 채점기가 건너뛴다)
- 기대 등급: `standard`
- 기대 산출물: 조사 결과 + 답변

## 프롬프트

상태: open / 담당: 나 / 채널: email

고객 (2026-10-06 10:20):
안녕하세요. 온프렘에 Oracle 19c EE 운영 DB 가 한 대 있습니다.

1. Amazon RDS for Oracle 인스턴스를 온프렘 primary 의 Data Guard standby 로 붙일 수 있나요?
2. 안 된다면 AWS 에서 Data Guard standby 를 두는 방법은 무엇인가요?

아직 검토 단계이고 계정에 만든 리소스는 없습니다.

## 기대 결과

답이 있는 질문이다. 공식 문서를 찾아 답하면 된다. **이 티켓에서 넘어진 사람은 없다** — 고객이 틀린 전제를 말하지 않았고,
우리가 틀리게 답한 적도 없고, 사람이 남기라고 하지도 않았다.

### 절차 (기계 채점: `python3 scripts/check_ticket_record.py 900108`)

- [ ] `tickets/900108.md` 가 생성됐다
- [ ] `## 교훈 후보` 가 채워져 있다 (비어 있지 않다)

### 경계 (사람 채점) — 여기가 본체다

- [ ] `## 교훈 후보` 가 `- 없음` 이다
- [ ] 조사에서 알게 된 사실(RDS 는 외부 primary 의 standby 가 될 수 없다 등)을 `종류: pitfall` 로 올리지 않았다

## 이 케이스가 노리는 것

후보는 승인자가 하나씩 읽는다. 지식이 전부 후보로 오면 진짜 함정이 묻힌다.
