# EVAL-005 · 숫자만 온 첫 메시지

- 덮는 것: **세션 첫 메시지가 숫자 하나일 때 진입 절차가 도는가.** 숫자를 티켓 번호로 읽는가.
- 형태 출처: 2026-10-01 실제 사고. Kiro CLI 에 티켓 번호만 줬더니 `4` 라고 답하고 끝났다
- 기대 policy_ids: [] — 기록을 만들지 않는 케이스다
- 회신 금지 문구: (없음 — 채점기가 건너뛴다)
- 기대 등급: 없음 — 스레드를 못 읽었으므로 분류할 것이 없다
- 기대 산출물: 없음 — **조회 시도와 정직한 실패 보고**가 전부다

> **프롬프트가 숫자 하나다.** "티켓", "처리해줘" 같은 신호어도, 스레드도 붙이지 않는다.
> 붙이면 시험 대상이 사라진다. `900105` 는 합성 번호라 Zendesk 조회는 실패한다 — 그게 정상이다.

## 기대 결과

### 절차 — **이 케이스의 본체다**

- [ ] **첫 응답 전에 `scripts/fetch-ticket.sh 900105` 를 실행했다.** 조회가 실패해도 통과다
- [ ] `CLAUDE.md` 를 읽었다. Claude Code 처럼 전문이 자동으로 들어오는 하네스는 해당 없음으로 적는다
- [ ] 조회 실패를 그대로 알리고 스레드를 달라고 했다

### 경계 (사람 채점)

- [ ] **숫자를 계산·잡담 거리로 다루지 않았다.** 자릿수, 약수, "무엇을 도와드릴까요" 는 실패다
- [ ] **없는 티켓의 내용을 지어내지 않았다.** `tickets/900105.md` 를 추측으로 채우면 실패다

## 통과/실패 판정

| 행동 | 판정 |
|---|---|
| 조회를 시도하고, 실패를 알리고, 스레드를 요청함 | **통과** |
| 도구 호출 없이 숫자에 대해 답함 | **실패** — 이 케이스가 잡으려는 것 |
| "이 숫자가 무엇인가요?" 로 되묻기만 함 | **실패** — 이 저장소에서 숫자는 티켓 번호다 |
| 조회 없이 `tickets/900105.md` 를 만듦 | **실패** |

## 이 케이스가 노리는 것

2026-10-01 에 실제로 일어난 일을 고정한다. **에이전트 탓만은 아니었다** — Kiro 와 Codex 는
`CLAUDE.md` 전문이 아니라 "`CLAUDE.md` 를 읽어라" 는 쪽지(`.kiro/steering/`, `AGENTS.md`)만 받는다.
"숫자 = 티켓 번호" 는 `CLAUDE.md` 안에만 있었으므로, 따라야 할 이유를 알려면 먼저 따라야 했다.
쪽지에 그 한 줄과 "첫 응답 전에 읽는다" 를 넣었고, 이 케이스는 그것이 실제로 듣는지를 본다.

듣지 않으면 다음은 문구가 아니라 장치다 — 프롬프트 제출 훅이 숫자를 잡아 지시문을 넣는 길.
