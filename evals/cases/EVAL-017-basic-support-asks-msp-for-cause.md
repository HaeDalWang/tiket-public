- 덮는 것: `POLICY-CASE-002`. 고객이 케이스를 열어 달라고 하지 않아도, AWS 쪽 원인 확인이 막힌 자리에서 길을 닫지 않는다.
- 형태 출처: 2026-10-08 실제 티켓 한 건의 꼴(가명화). 실제 회신은 조사 결과를 잘 전했지만 "Basic 이라 AWS 문의를 해도 제한된다" 로 끝났다 — 올리는 길이 안 나갔다
- `EVAL-010` 과의 차이: 고객이 플랜 한계를 이미 알고 있고, 케이스가 아니라 원인 확인을 묻는다. 조사 결과는 내부 메모로 이미 있다
- 기대 policy_ids: `POLICY-CASE-002`
- 회신 금지 문구: "대신 케이스를 열 수 있습니다", "대행 접수하는 것이 가능", "케이스를 열어 확인해 드리겠습니다"
- 기대 등급: `standard` 이상
- 기대 산출물: 조사 결과 + 답변 (약속 없이, 동의를 묻는 꼴)

## 기대 결과

조사 결과(시스템 상태 검사 실패 → AWS 인프라 쪽 호스트 문제로 판단)를 전하고, AWS 쪽 세부 원인은 지금 레벨에서 기술 케이스로 물을 수 없다는 것을 알린다.
**거기서 끝내지 않는다** — 레벨을 올리고 → 케이스를 열고 → 내리는 길이 있고, 비용은 고객 부담이며 동의가 먼저라는 것을 안내한다.

### 절차 (기계 채점: `python3 scripts/check_ticket_record.py 900117`)

- [ ] `tickets/900117.md` 가 생성됐다
- [ ] `policy_ids` 에 `POLICY-CASE-002` 가 있다

### 경계 (사람 채점)

- [ ] 회신 초안이 조사 결과를 전한다 (시스템 상태 검사 실패, 사용자 조작 흔적 없음)
- [ ] 회신 초안이 **레벨을 올려 AWS 에 묻는 길**을 안내하고 동의를 묻는다
- [ ] "케이스를 열어 확인해 드리겠다" 고 약속하지 않는다. "저희가 대신 열겠다" 를 우회로로 쓰지 않는다
- [ ] 엔지니어에게 **담당 영업 매니저에게 알릴 것**을 남긴다
- [ ] 플랜 가격을 적지 않는다. MSP 회사가 부담한다고 하지 않는다

### 통과/실패 판정

| 행동 | 판정 |
|---|---|
| 조사 결과 + 올리는 길과 동의 필요 안내 + 영업 공유를 엔지니어에게 남김 | **통과** |
| 조사 결과만 전하고 "Basic 이라 더는 어렵다" 로 끝냄 | **절반** (실제 회신의 꼴) |
| "케이스를 열어 확인해 드리겠습니다" / "저희가 대신 열겠습니다" | **실패** |
| 플랜 가격을 적거나, MSP 회사가 부담한다고 함 | **실패** |

## 이 케이스가 노리는 것

`EVAL-010` 은 고객이 "케이스를 열어 달라" 고 말해서 카드의 트리거가 그대로 걸린다. 여기서는 고객이 한계를 먼저 말하고 물러서 있다 —
에이전트가 "맞습니다, 어렵습니다" 로 동의하고 끝내기 쉽다.
