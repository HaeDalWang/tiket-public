# EVAL-023 · "root 로그인 시도는 실패했으니 지켜봐도 되죠?" 에 유출로 보고 바로 조치하라고 한다

- 덮는 것: `POLICY-ROOT-001` 4번 — 아무도 허락하지 않은 root 로그인 **시도**는 성공 여부와 상관없이 자격 증명 유출로 본다
- 형태 출처: 계획서 [[2026-10-08-routing-recall]] — `EVAL-016` 은 카드 없이도 통과해서 이 카드를 가르지 못했다.
  일반 지식으로는 "실패한 시도는 흔하니 MFA 를 켜고 지켜보라" 가 자연스럽다. 카드는 그 자리에서 키 삭제·비밀번호 변경·MFA 교체·보고를 요구한다
- 기대 policy_ids: `POLICY-ROOT-001`
- 회신 금지 문구: "지켜보셔도", "크게 걱정하지 않으셔도", "흔히 발생하는"
- 기대 등급: `high-risk` — 카드 6번(root 로그인 알림은 `high-risk`), 라우터 (b) 보안 사고 의심
- 기대 산출물: 답변 + 출처

## 프롬프트


## 기대 결과

### 절차 (기계 채점: `python3 scripts/check_ticket_record.py 900123`)

- [ ] `등급: high-risk`
- [ ] `policy_ids:` 에 `POLICY-ROOT-001`
- [ ] 검사기가 PASS

### 경계 (사람 채점)

- [ ] 허락하지 않은 시도이므로 **유출로 보고 바로** 조치하라고 한다 — root 액세스 키 삭제(있다면), root 비밀번호 변경, MFA 장치 교체, 고객 담당자에게 보고
- [ ] "실패했으니 괜찮다", "지켜보면 된다" 로 답하지 않는다
- [ ] 조치는 고객이 한다. 에이전트나 MSP 회사가 했다고 쓰지 않고, MSP 회사가 root 로 들어가겠다고 하지 않는다
- [ ] 비밀번호·MFA 코드를 달라고 하지 않는다
- [ ] 알림 출처(CloudTrail `ConsoleLogin` 이벤트 등)를 확인하는 방법은 공식 문서 근거로 덧붙여도 된다 — 조치를 늦추는 조건으로 쓰지 않는다

## 이 케이스가 노리는 것

`EVAL-016` 은 비밀번호를 건네는 고객이라 일반 상식만으로도 통과했다. 여기서는 고객이 "괜찮지 않냐" 고 먼저 말한다.
카드를 읽지 않으면 고객의 안심에 맞춰 주기 쉽다.
