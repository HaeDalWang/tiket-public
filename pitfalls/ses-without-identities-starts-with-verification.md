# 신원(이메일·도메인)이 하나도 없는 SES 계정에 "프로덕션 액세스 요청" 부터 안내하면 틀린다 — 콘솔은 신원 확인부터 연다

## 무엇을 하면 틀리는가

- "SES 를 신청해 달라", "SES 쓰게 해 달라" 는 요청에 바로 프로덕션 액세스(샌드박스 해제) 요청 절차를 안내하고, 신원 확인은 "해 두면 빠르다" 는 권장으로만 적는다.

## 실제로 있었던 일

- 2026-10-21: 첫 초안이 프로덕션 액세스 요청부터 안내하고 신원 확인을 권장으로만 적었다. 담당 엔지니어가 콘솔 화면이 "이메일 주소와 전송 도메인을 확인하세요" 를 먼저 띄우고
  고객 도메인이 아직 없다는 것을 전해 초안을 고쳤다.

## 확인된 사실

- 새 SES 계정은 리전마다 샌드박스로 시작한다. 샌드박스에서는 검증된 주소·도메인으로만 보낼 수 있고 하루 200통·초당 1통이다
  (https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html).
- 같은 문서: 신원을 하나도 만들지 않았으면 콘솔에 **계정 설정 마법사**가 뜬다. 신원이 있으면 Get set up 페이지가 뜨고, **그중 검증된 도메인이 있어야**
  Get set up 페이지에서 바로 프로덕션 액세스를 요청할 수 있다. 문서는 이것을 승인을 빠르게 하는 best practice 라고도 쓴다.
- 프로덕션으로 나간 뒤에도 From·Source·Sender·Return-Path 로 쓰는 신원은 모두 검증해야 한다(같은 문서).

## 해야 할 것

1. 순서를 신원 확인 → 프로덕션 액세스 요청으로 안내한다. 도메인 신원은 콘솔이 주는 DNS 레코드를 고객 DNS 에 넣어야 검증된다고 적는다.
2. 고객에게 보낼 도메인이 아직 없으면 그것부터 묻는다.
3. 요청은 계정 소유자가 직접 한다 — MSP 회사 역할은 읽기 전용이라 대신 제출할 수 없다(`POLICY-ACCESS-002`).

## 다시 쓰기 전에 확인할 것

- SES 문서의 마법사·Get set up 분기 문구가 그대로인지.
