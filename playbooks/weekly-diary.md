# 일기(주간회고) 초안

팀이 주간회고를 "일기" 라고 부른다. "일기 써줘", "주간회고 정리해줘" 가 오면 이 문서대로 한다.
**고객 건이 아니다** — 티켓 기록을 만들지 않고, 정책 카드를 찾지 않는다.

## 순서

1. `python3 scripts/weekly_diary.py` 를 돌린다 (`python3` 가 없으면 `python`). 다른 주면 `--week <그 주 월요일>`.
   그 주의 `tickets/` 기록과 Zendesk 의 티켓 수 셋이 나온다.
2. 아래 양식대로 초안을 **화면에** 쓴다.
3. 초안 뒤에, 재료가 없어 비워 둔 칸과 사람이 확인할 것을 한두 줄로 말하고, **사이트에 임시저장할지 묻는다.**
4. 사람이 "저장해" 라고 하면 그때만 아래처럼 보낸다. 묻지 않고 보내지 않는다. 키가 없다고 나오면 그 안내를 그대로 전하고, 초안은 붙여 넣게 둔다.

```bash
python3 scripts/weekly_diary_save.py --week <그 주 월요일> <<'JSON'
{"workHighlights": "- …", "ticketsNew": 1, "ticketsInProgress": 1, "ticketsDone": 2}
JSON
```

   - 화면에 보여 준 초안 그대로 보낸다. `(직접 작성)` 인 칸은 넣지 않는다. 숫자를 못 읽었으면 숫자 칸도 넣지 않는다.
   - 스크립트는 **이미 적혀 있는 칸을 건드리지 않고**, 제출된 회고에는 손대지 않는다. 그 결과를 그대로 전한다. `--overwrite` 는 사람이 덮으라고 했을 때만 쓴다.
   - 임시저장까지다. **제출은 사람이 웹에서 한다** — 제출 API 를 직접 부르지 않는다.

## 양식 — 사이트의 칸 그대로

```text
신규 티켓 N · 진행 중 티켓 N · 종료 티켓 N

[주요 업무 현황]
- <고객사> — <무엇을 했나 한 줄> (<상태>)

[주요 계획 / Action Item]
(직접 작성)

[프로젝트/과제 현황(TOPS)]
(직접 작성)

[기타 사항]
(직접 작성)
```

## 쓰는 법

- **주요 업무 현황** — 기록 한 건에 한 줄. 같은 고객은 붙여 둔다. 고객이 물은 것과 한 일을 한 문장으로 줄인다.
  기록에 없는 일은 쓰지 않는다 — 티켓 밖에서 한 일은 사람이 덧붙인다.
- **Action Item·TOPS·기타 사항** — 티켓 기록에는 재료가 없다. `(직접 작성)` 으로 둔다. 지어내지 않는다.
  Action Item 은 출장·자격증·교육·미팅 같은 티켓 밖 일정이다. 진행 중인 티켓을 옮기지 않는다 — 주요 업무 현황과 겹친다.
- **숫자** — 스크립트가 낸 값을 그대로 적는다. 못 읽었다고 나오면 `N` 으로 두고 그렇다고 말한다. 0 으로 적지 않는다.
- 사이트 편집기는 제목·글머리표 서식이 없다. 평문과 `- ` 로만 쓴다.

## 하지 않는 것

- 묻지 않고 사이트에 보내지 않는다. 제출하지 않는다.
- 초안을 파일로 저장하지 않는다 — 실제 고객사명이 들어간다. 저장 스크립트에도 표준 입력으로 넘긴다.
- 계정 ID, 연락처, 자격증명, 비용 수치를 옮기지 않는다. 고객사명과 한 일만 적는다.
- 다른 사람의 건수나 이름을 적지 않는다. 내 것만 쓴다.
